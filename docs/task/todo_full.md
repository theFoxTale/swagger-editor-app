# Функциональные требования (максимум 550 баллов)

## 1. Шапка приложения (+60)

- [ ] (+15) Неавторизованные пользователи видят кнопки «Войти» и «Зарегистрироваться» в правом верхнем углу шапки.
- [ ] (+10) Авторизованные пользователи видят кнопки «История» и «Выйти» в правом верхнем углу шапки.
- [ ] (+10) Ссылка на страницу «О проекте» доступна в шапке и подвале.
- [ ] (+10) Если токен истек/недействителен, пользователь перенаправляется с приватных маршрутов на главную страницу.
- [ ] (+15) Нажатие на кнопку «Войти» / «Зарегистрироваться» перенаправляет на маршрут с соответствующей формой.

## 2. Вход / Регистрация (+50)

- [ ] (+10) Кнопки «Войти» / «Зарегистрироваться» / «Выйти» присутствуют везде, где должны быть.
- [ ] (+20) Реализована клиентская валидация (формат email, надёжность пароля: минимум 8 символов, как минимум одна буква, одна цифра, один специальный символ, поддержка Unicode).
- [ ] (+10) После успешного входа пользователь перенаправляется на главную страницу.
- [ ] (+10) Если пользователь уже авторизован и пытается перейти на маршруты входа/регистрации, он перенаправляется на главную страницу.

## 3. Редактор Swagger (+120)

- [ ] (+25) Поддерживается загрузка/вставка схем OpenAPI/Swagger в форматах JSON и YAML.
- [ ] (+20) Реализовано автоматическое определение формата (JSON или YAML).
- [ ] (+20) Переключение формата с автоматической конвертацией (JSON ↔ YAML) работает корректно.
- [ ] (+15) Реализована валидация схемы с индикацией ошибок.
- [ ] (+10) Авторизованные пользователи могут сохранять схемы; при следующем входе сохраненная схема автоматически восстанавливается в редакторе.
- [ ] (+10) Просмотрщик автоматически заполняется эндпоинтами при валидной схеме.
- [ ] (+20) Адаптивный разделенный вид подстраивается под ориентацию экрана (горизонтальная/вертикальная).

## 4. Просмотрщик Swagger (+120)

- [ ] (+20) Список эндпоинтов отображается с группировкой по пути/методу.
- [ ] (+25) Детали эндпоинта показывают метод, путь и все типы параметров (path, query, header, cookie).
- [ ] (+20) Отображается схема запроса и примеры полезной нагрузки.
- [ ] (+25) Отображается схема ответа, примеры и все поддерживаемые коды состояния.
- [ ] (+20) Реализована функциональность Try-It-Out: заполнение параметров, заголовков и тела; выполнение запросов; отображение ответов.
- [ ] (+10) Реализована кнопка «Сгенерировать cURL» с возможностью копирования в буфер обмена.

## 5. История и аналитика (+70)

- [ ] (+15) История и аналитика генерируются на сервере; при отсутствии запросов в базе отображается информационное сообщение со ссылками на редактор/просмотрщик.
- [ ] (+10) Запросы отображаются в порядке убывания времени (сначала новые).
- [ ] (+45) На серверной стороне записывается и отображается следующая аналитика: длительность запроса, код состояния ответа, временная метка запроса, метод запроса, размер запроса, размер ответа, детали ошибки, эндпоинт/URL.

## 6. Страница «О проекте» (+25)

- [ ] (+5) Страница «О проекте» доступна всем пользователям (публичный маршрут).
- [ ] (+5) Страница содержит информацию о курсе RS School.
- [ ] (+10) Страница содержит информацию об участниках команды (имена, роли, ссылки на GitHub).
- [ ] (+5) Дизайн страницы «О проекте» соответствует общему дизайну приложения.

## 7. Общие требования (+55)

- [ ] (+30) Поддерживается несколько (как минимум 2) языков с переключателем i18n в шапке.
- [ ] (+10) Реализована липкая шапка с анимацией при закреплении.
- [ ] (+10) Ошибки отображаются в понятном пользователю формате.
- [ ] (+5) Приватные маршруты защищены должным образом (401 при отсутствии аутентификации).

## 8. Видео на YouTube (+50)

- [ ] (+50) В pull request добавлена ссылка на YouTube-видео длительностью 5–7 минут, демонстрирующее все реализованные функции.

# Технические требования (штрафы)

- [ ] (-200) Использование любого фреймворка, не входящего в обязательный список (**React Router 7 (Framework mode)**, **Next.js (App Router)**, **Vinext**, **Tanstack Start**, **Waku**).
- [ ] (-20 за каждое) Использование `@ts-ignore` или `any` (поиск по репозиторию).
- [ ] (-10 за каждый случай) Наличие _code-smells_ (божественный объект, дублирование кода), закомментированных участков кода.
- [ ] Покрытие тестами (применяется одно из):
  - [ ] (-50) Покрытие операторов ниже 80% (≥70%)
  - [ ] (-100) Покрытие операторов ниже 70% (≥50%)
  - [ ] (-150) Все метрики покрытия ниже 50%
  - [ ] (-250) Отсутствие тестов
- [ ] (-50 за каждый) Один из обязательных маршрутов с ленивой загрузкой не загружается лениво.
- [ ] (-20 за каждое) Наличие ошибок и предупреждений в консоли.
- [ ] (-20 за каждый) Наличие в консоли результатов выполнения `console.log`.
- [ ] (-50) HTTP-статусы 4xx и 5xx отображаются как ошибки не в разделе ответа.
- [ ] (-150) Отсутствие инструмента линтинга.
- [ ] (-100) Отсутствие инструмента форматирования.
- [ ] (-100) Отсутствие хуков husky.
- [ ] (-50) Стандартная иконка Vite/Next.js.
- [ ] (-100) Создание коммитов после дедлайна в период кросс-чека.
- [ ] (-10) Pull Request не соответствует руководству (включая чекбоксы в разбалловке).
- [ ] (штраф) Использование неправильных названий репозиториев или веток (на усмотрение администрации).
