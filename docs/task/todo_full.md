# Функциональные требования (максимум 550 баллов)

## 1. Шапка приложения (+60)

- [x] (+15) Неавторизованные пользователи видят кнопки «Войти» и «Зарегистрироваться» в правом верхнем углу шапки.
- [x] (+10) Авторизованные пользователи видят кнопки «История» и «Выйти» в правом верхнем углу шапки.
- [x] (+10) Ссылка на страницу «О проекте» доступна в шапке и подвале.
- [ ] (+10) Если токен истек/недействителен, пользователь перенаправляется с приватных маршрутов на главную страницу.
  - Частично: приватный `/history` защищён через Supabase `getUser()` в `src/proxy.ts`, но сейчас открывается `/401`, а не редирект на `/`.
- [x] (+15) Нажатие на кнопку «Войти» / «Зарегистрироваться» перенаправляет на маршрут с соответствующей формой.

## 2. Вход / Регистрация (+50)

- [x] (+10) Кнопки «Войти» / «Зарегистрироваться» / «Выйти» присутствуют везде, где должны быть.
- [ ] (+20) Реализована клиентская валидация (формат email, надёжность пароля: минимум 8 символов, как минимум одна буква, одна цифра, один специальный символ, поддержка Unicode).
  - Частично: длина, буква (ASCII), цифра и спецсимвол есть в `AuthForm`; строгая email-проверка и Unicode-буквы ещё не закрыты; `src/lib/validation.ts` пока не используется формой.
- [x] (+10) После успешного входа пользователь перенаправляется на главную страницу.
- [x] (+10) Если пользователь уже авторизован и пытается перейти на маршруты входа/регистрации, он перенаправляется на главную страницу.

## 3. Редактор Swagger (+120)

- [x] (+25) Поддерживается загрузка/вставка схем OpenAPI/Swagger в форматах JSON и YAML.
- [x] (+20) Реализовано автоматическое определение формата (JSON или YAML).
- [x] (+20) Переключение формата с автоматической конвертацией (JSON ↔ YAML) работает корректно.
- [x] (+15) Реализована валидация схемы с индикацией ошибок.
- [x] (+10) Авторизованные пользователи могут сохранять схемы; при следующем входе сохраненная схема автоматически восстанавливается в редакторе.
- [x] (+10) Просмотрщик автоматически заполняется эндпоинтами при валидной схеме.
- [x] (+20) Адаптивный разделенный вид подстраивается под ориентацию экрана (горизонтальная/вертикальная).

## 4. Просмотрщик Swagger (+120)

- [x] (+20) Список эндпоинтов отображается с группировкой по пути/методу.
- [x] (+25) Детали эндпоинта показывают метод, путь и все типы параметров (path, query, header, cookie).
- [x] (+20) Отображается схема запроса и примеры полезной нагрузки.
- [x] (+25) Отображается схема ответа, примеры и все поддерживаемые коды состояния.
- [x] (+20) Реализована функциональность Try-It-Out: заполнение параметров, заголовков и тела; выполнение запросов; отображение ответов.
- [x] (+10) Реализована кнопка «Сгенерировать cURL» с возможностью копирования в буфер обмена.

## 5. История и аналитика (+70)

- [x] (+15) История и аналитика генерируются на сервере; при отсутствии запросов в базе отображается информационное сообщение со ссылками на редактор/просмотрщик.
- [x] (+10) Запросы отображаются в порядке убывания времени (сначала новые).
- [ ] (+45) На серверной стороне записывается и отображается следующая аналитика: длительность запроса, код состояния ответа, временная метка запроса, метод запроса, размер запроса, размер ответа, детали ошибки, эндпоинт/URL.
  - Частично: страница истории читает и показывает данные из `request_history`, но Try-It-Out / `/api/proxy` пока не записывает аналитику в БД.

## 6. Страница «О проекте» (+25)

- [x] (+5) Страница «О проекте» доступна всем пользователям (публичный маршрут).
- [x] (+5) Страница содержит информацию о курсе RS School.
- [x] (+10) Страница содержит информацию об участниках команды (имена, роли, ссылки на GitHub).
- [x] (+5) Дизайн страницы «О проекте» соответствует общему дизайну приложения.

## 7. Общие требования (+55)

- [x] (+30) Поддерживается несколько (как минимум 2) языков с переключателем i18n в шапке.
- [x] (+10) Реализована липкая шапка с анимацией при закреплении.
- [x] (+10) Ошибки отображаются в понятном пользователю формате.
- [x] (+5) Приватные маршруты защищены должным образом (401 при отсутствии аутентификации).

## 8. Видео на YouTube (+50)

- [ ] (+50) В pull request добавлена ссылка на YouTube-видео длительностью 5–7 минут, демонстрирующее все реализованные функции.
